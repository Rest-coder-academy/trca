8 · Rules

Don't tell a person something worked when it didn't.

No success toast before a 2xx. A silent failure on the enquiry form costs a ₹35,000 enrolment and produces no error anywhere.

Don't ship a control that does nothing.

The navbar hamburger currently renders at every width from 600px up, but the drawer it opens is xs-only — on tablet and desktop it is a dead button sitting next to a working nav.

Don't ship an uncompressed screenshot.

One review image is 3.8MB and the page totals about 7MB. Target the whole page under 1MB. Export at 2× display size, WebP, and set width and height so nothing reflows.

Don't hard-code a date in a component.

Batch dates read 24-05-2025 today. Dates live in one data file, and a past date renders as "Batch closed", never as an upcoming batch.

Do put the proof above the fold.

Company placements and student outcomes are the reason someone enrols. They currently sit four sections down, under a generic mission paragraph.

Do use a token for every value.

If a colour, size or radius isn't in design/tokens.css, it doesn't go in a component. New value needed? Add it here first.

Do keep every tap target at 44px or more.

Including the floating WhatsApp button and the drawer menu rows.
